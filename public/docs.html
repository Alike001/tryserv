About XP and progress

Each of four lessons awards 20 XP once, up to 80 XP, stored only in this browser. The three debugging repairs have a separate completion count. You can reset or lose that local progress by clearing browser storage. TrySERV does not issue a certificate or a verified credential.

03
REAL SERV REASONING

Where OpenServ powers the product

Our lesson companion uses SERV Reasoning through its OpenAI-compatible Chat Completions API. The lesson context and a visitor's question are sent by TrySERV's server; a successful response shows its model, completion identifier, usage, and latency. It is live inference, not a prerecorded chatbot reply.

Visitor asks a lesson question↓ Server checks the limited guest budget↓ SERV Chat Completions processes the question↓ Response + source link + actual model metadata

The AI explanation may still be mistaken. TrySERV supplies an official source for human checking. Answers to quizzes and request-structure validation are deterministic, not graded by the model.

Free public tutoring has limits

At this stage, guest tutoring allows up to two requests per approximate visitor identity per UTC day and a shared lifetime pilot budget of 24 guest calls. Remaining requests are shown in the learning studio when the budget service is available. The quota is stored in a database; when it is exhausted or unavailable, paid guest calls stop but free lessons still work. These limits can change after measured cost and abuse review.

06
SYSTEM DESIGN

Small architecture, explicit boundaries

Browser

Lessons, forms, local XP, debugging completion, user-visible feedback.

TrySERV Node server

Serves the pages, grades exercises, validates request shapes, verifies guest allowance.

Neon PostgreSQL

Stores bounded public tutor request counts—not learner XP or personal accounts.

OpenServ SERV API

Processes authorized tutoring questions. The API key stays on the server.

The hosted app runs on Render. There is no wallet proof, token reward, blockchain settlement, or autonomous agent deployment in this product. The demo request builder is a learning tool, not a guarantee that a user's own integration works in production.

07
SAFETY & TRANSPARENCY

What TrySERV stores—and doesn't

  • On your device: completed lesson IDs, earned local XP, and completed debugging mission IDs.
  • On the server: bounded tutor usage counters, using a pseudonymous keyed visitor identifier rather than storing raw browser identity in the quota table.
  • Sent for live tutoring: the question you type and the selected lesson context; don't enter passwords, private keys, confidential code, or sensitive personal information.
  • Not stored as a learner account: no registration, persistent login profile, official OpenServ certification, or verified identity.
  • Unaudited learning pilot: the code has automated tests, but this isn't a guarantee of security or commercial uptime.

COMMON QUESTIONS

Before you begin

Is TrySERV made or endorsed by OpenServ?

No. TrySERV is an independent learning companion. It links to OpenServ's official sources, but is not affiliated with or endorsed by OpenServ.

Do I need a SERV API key to complete the lessons?

No. All four lessons, exercise grading, XP and the request-debugging lab work without an API key. Public SERV tutoring is available only within a finite shared trial allowance.

Does a validated request mean the API call succeeded?

No. Validation checks the supported structure locally through TrySERV's server. It is a preview unless an explicitly authorized live request is made and a genuine completion is returned.

Why can the AI tutor stop answering?

Because the pilot uses paid SERV inference, public tutoring has a durable budget. When exhausted, the no-cost learning and debugging paths remain accessible.

Will my XP follow me to another device?

No. Lesson XP and completed debugging scenarios are stored in the current browser only. They are neither account-based nor wallet-verified.
